# cAIsdev — инструкции для Claude Code

## Что это за проект

Внутренний инструмент команды: симулятор обратной связи от стейкхолдеров для продуктовых команд. Аналитик загружает документ (ЧТЗ, user story, концепцию) — 10 ИИ-персон, симулирующих HRM-заказчиков, дают структурированную обратную связь.

Монетизация не планируется. Аудитория — аналитики и PM внутри одной команды.

## Структура проекта

```
cAIsdev/
├── hrm_review.html          — текущий прототип (HTML/CSS/JS, без фреймворков)
├── project_context.md       — полный контекст продукта
└── knowledge_base/
    ├── README.md            — навигация по базе знаний
    ├── 01_product/          — Lean Canvas, брейншторм-решения, ИПР-тест
    ├── 02_personas/         — профили персон (краткие и углублённые)
    ├── 03_ux_design/        — user flows, экспорт, роли пользователей
    └── 04_architecture/     — верхнеуровневая архитектура MVP
```

## Технический стек

- **Прототип**: один HTML-файл, чистый JS, без сборки и фреймворков
- **AI**: DeepSeek API (`deepseek-chat`), совместим с OpenAI SDK
- **Следующий шаг**: Node.js/FastAPI backend как прокси (решает CORS) + Google Sheets API
- **Планируемый переход**: DeepSeek → Claude API (`claude-sonnet-4-6`) при масштабировании

## Персоны

Три набора, хранятся в `knowledge_base/02_personas/`:
- **HRM general** (10 персон) — краткие в прототипе, углублённые в `hrm_deep_profiles.md`
- **KPI module** (3 персоны) — написаны ведущим аналитиком
- **HireFlow/ATS** (3 персоны) — из обучающего курса

Структура ответа каждой персоны: первое впечатление → вопросы и возражения (3-5) → вывод.

## Принятые решения (не переспрашивать)

- Экспорт результатов → Google Sheets (основной формат)
- Коллективный режим → шеринг по ссылке, не real-time
- Режим дискуссии → опциональный переключатель, не дефолт
- Авторизация → нет, доступ по прямой ссылке
- Роль пользователя → указывается при старте, влияет на детализацию ответов персон
- Загрузка файлов → обязательная функция (PDF, DOCX, MD)

## Первые приоритеты

1. **ИПР-тест** (`knowledge_base/01_product/validation_test_ipr.md`) — главная валидация гипотезы
2. Обновить промпты прототипа углублёнными профилями из `hrm_deep_profiles.md`
3. Backend-прокси для CORS + Google Sheets API

## Чего не делать

- Не предлагать авторизацию (решено: не нужна для MVP)
- Не предлагать React/Vue/фреймворки — сознательный выбор чистого JS
- Не добавлять монетизацию, аналитику использования и прочее в Приоритет 3 без явного запроса
- Не трогать структуру персон без запроса — промпты тщательно выверены
