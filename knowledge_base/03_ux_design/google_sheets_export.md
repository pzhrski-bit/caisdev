# Google Sheets Export — Структура данных

---

## Концепция

Результат каждой сессии уходит в Google Sheets. Это основной формат хранения и шеринга результатов.

Один Google Sheet = одна сессия (или набор сессий по проекту).

---

## Структура листов

### Лист 1: Сводная по сессии

| Колонка | Содержание |
|---------|-----------|
| Персона | Название роли |
| Первое впечатление | Краткое (1-2 предложения) |
| Кол-во вопросов/возражений | Число |
| Ключевые вопросы | Топ-3 вопроса от персоны |
| Вывод | "Можно брать в работу" / "Нужно доработать" / "Требует обсуждения" |
| Статус | Обработано / В работе / Игнорируем |

### Лист 2: Контекст сессии

| Поле | Значение |
|------|----------|
| Дата | — |
| Пользователь | Роль в проекте (аналитик / PM / ...) |
| Набор персон | HRM / KPI / HireFlow |
| Фаза проекта | Концепция / Требования / Готовая функциональность |
| Что анализировалось | Название документа или краткое описание |
| Дополнительный контекст | Что именно хотели проверить |

### Лист 3+: Ответ каждой персоны (по одному листу)

Полный ответ персоны с форматированием:
1. Первое впечатление
2. Вопросы и возражения (пронумерованный список)
3. Вывод

## Технические варианты реализации

### Вариант A: Google Apps Script (без backend)
- Скрипт вызывается из браузера через API
- Данные передаются напрямую в Sheet
- Плюс: не нужен отдельный сервер
- Минус: сложнее с авторизацией

### Вариант B: Backend → Google Sheets API
- Node.js / Python backend делает запросы к Sheets API
- Плюс: проще управлять токенами
- Минус: нужен backend (который всё равно нужен для CORS)

**Рекомендация**: Вариант B, так как backend всё равно нужен для проксирования AI-запросов.

## Формат ссылки для шеринга

При экспорте сессии — создаётся ссылка на Google Sheet с правами "просмотр для всех по ссылке". Ссылка сохраняется в инструменте для повторного доступа.
