# User Flows — cAIsdev

---

## Основной сценарий (одиночный режим)

```
1. Открыть инструмент по ссылке
2. Выбрать набор персон (HRM / KPI / HireFlow)
3. Указать свою роль (аналитик / PM / пресейл / PO / другое)
4. Выбрать фазу проекта (Концепция / Требования / Готовая функциональность)
5. Загрузить документ (PDF/DOCX/MD) или вставить текст
6. [опционально] Добавить свободный контекст: что именно хочешь проверить
7. Выбрать персоны для анализа (часть или все)
8. Запустить анализ
9. Дождаться ответов (последовательно с typing indicator)
10. Просмотреть результаты
11. Экспортировать в Google Sheets
```

## Коллективный режим (шеринг по ссылке)

```
1. Аналитик проводит сессию (шаги 1-10 выше)
2. После завершения: нажать "Поделиться сессией"
3. Получить ссылку
4. Отправить ссылку коллегам
5. Коллега открывает ссылку — видит:
   - Исходный документ (или текст)
   - Контекст: роль пользователя, фаза, набор персон
   - Все ответы персон
   - Вопросы, которые задавались в дополнительном контексте
6. [опционально] Добавить свой комментарий / запустить дополнительный анализ
```

**Что именно шарится**:
- Исходный документ
- Ответы персон
- Заданный контекст
- Вопросы, которые всплывали в процессе
- Идеи, которые были отвергнуты (если пользователь их пометил)

## Режим дискуссии (опциональный, включается отдельно)

```
1. После первого раунда ответов: включить "Режим дискуссии"
2. Персоны видят ответы друг друга
3. Каждая персона реагирует на позиции других (не только на документ)
4. Выявляются конфликты между ролями:
   - CFO vs CIO (стоимость vs надёжность)
   - HRD vs Руководитель подразделения (процессы vs простота)
   - CISO vs все (безопасность vs удобство)
5. Результат дискуссии: список конфликтных точек + позиции сторон
```

**Когда использовать дискуссию**:
- При наличии конфликтующих требований в документе
- Когда нужно понять, чьи интересы приоритетнее
- При подготовке к сложной презентации стейкхолдерам

## Роль пользователя и её влияние на персон

| Роль пользователя | Как это влияет на ответы персон |
|------------------|--------------------------------|
| Аналитик | Персоны дают детальные вопросы по полноте требований, указывают пробелы |
| PM / PO | Персоны фокусируются на бизнес-ценности и приоритизации |
| Пресейл | Персоны дают высокоуровневые возражения и вопросы ROI |
| Разработчик | Персоны акцентируют нефункциональные требования |

**Принцип**: роль пользователя не меняет персону, но влияет на уровень детализации и терминологию ответов.
