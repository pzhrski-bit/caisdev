# Валидационный тест: ИПР через ИИ-персоны

> Приоритет: КРИТИЧНО — это главный test продуктовой гипотезы

---

## Суть теста

Сравнить качество обратной связи от ИИ-персон с результатами **реального кастдева**, который уже проводился по теме ИПР (индивидуальный план развития).

Если ИИ-персоны воспроизводят ключевые вопросы, возражения и инсайты реального кастдева — продукт решает заявленную задачу.

---

## Что нужно для теста

### Входные данные (уже есть)
- [ ] Документ ИПР (ЧТЗ или user story по модулю ИПР) — получить от команды
- [ ] Результаты реального кастдева по ИПР (записи, заметки, протоколы) — данные есть
- [ ] Фаза проекта для ИПР: скорее всего ТРЕБОВАНИЯ или ГОТОВАЯ ФУНКЦИОНАЛЬНОСТЬ

### Что нужно подготовить
- [ ] Выбрать набор персон для теста (предположительно: HRD крупной, Руководитель подразделения, CFO, Рядовой сотрудник)
- [ ] Использовать углублённые профили персон (не краткие)
- [ ] Запустить анализ через инструмент

### Критерии оценки

| Критерий | Измерение |
|----------|-----------|
| Совпадение ключевых вопросов | % вопросов из реального кастдева, воспроизведённых ИИ |
| Совпадение возражений | % возражений, совпавших по сути |
| Новые инсайты | Сколько вопросов ИИ не было в реальном кастдеве (хорошо или плохо?) |
| Качество формулировок | Субъективная оценка: похоже ли по стилю на реального стейкхолдера |

### Формат результата
Таблица сравнения: слева — вопросы из реального кастдева, справа — вопросы от ИИ-персон. Цветом отмечены совпадения.

---

## Когда проводить

После того, как в прототип загружены **углублённые профили персон** (не краткие). Краткие профили не дадут реалистичного поведения.

---

## Риски теста

- Реальный кастдев мог охватывать не тех стейкхолдеров — сложно сравнивать
- ИПР — чувствительная тема (данные сотрудников) — персоны должны это учитывать
- Если тест покажет низкое совпадение — нужно дорабатывать промпты, не отказываться от идеи
