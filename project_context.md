## 1. Суть продукта

**Название:** Каздев без каздева
**High level concept:** Симулятор обратной связи от стейкхолдеров для продуктовых команд

**Проблема:**
- У продуктовых команд нет единого заказчика — обратную связь от бизнеса получить сложно
- Каждый член команды общается с ИИ по-своему, единого формата нет
- Инсайты из часов стаются разрознено, теряются

**Решение:**
- Веб-приложение с панелью из 10 ИИ-персон, симулирующих реальных стейкхолдеров
- Аналитик загружает документ (ЧТЗ, user story, концепция, задача) — каждая выбранная персона даёт структурированную обратную связь от своей роли
- Единый формат ответа: первое впечатление → вопросы и возражения → оценка полноты и вывод

**Целевая аудитория:**
- Продуктовые аналитики
- Бизнес-аналитики
- Продавцы (пресейл, аккаунт-менеджеры)
- Владельцы продукта (PO/PM)

**Early adopters:** Аналитики в командах без прямого доступа к заказчику

**Контекст использования:** Продукт — HRM-система. Персоны симулируют заказчиков из HR-контекста.

## 2. Панель персон (10 ролей)

Каждая персона имеет:
- Уникальную роль и характер
- Свои метрики и фокус внимания
- Структуру ответа в 3 блоках
- Реакцию в зависимости от фазы проекта

| # | Роль | Ключевой фокус | Характер |
|---|------|---------------|----------|
| 1 | HRD крупной компании (500+) | Процессы, регламенты, масштаб | Профессиональный, осторожный |
| 2 | HRD небольшой компании (до 150) | Практичность, простота | Гибкий, прямой |
| 3 | Специалист C&B | Точность расчётов, интеграция с бухгалтерией | Дотошный, точный |
| 4 | Генеральный директор | ROI, риски, бизнес-ценность | Стратегический, краткий |
| 5 | Руководитель корп. университета | Обучение, карьерные треки, компетенции | Вдумчивый, системный |
| 6 | Безопасник (CISO/СБ) | Доступ, перcданные, 152-ФЗ | Скептичный, жёсткий |
| 7 | Руководитель подразделения (не HR) | Удобство, прозрачность по команде | Прагматичный, нетерпеливый |
| 8 | CFO | Бюджет, отчётность, TCO | Аналитичный, точный |
| 9 | CIO | Интеграции, SSO, надёжность | Системный, практичный |

**Структура ответа каждой персоны:**
1. **Первое впечатление** — 1-2 предложения
2. **Вопросы и возражения** — минимум 3-5 конкретных пунктов
3. **Оценка полноты и вывод** — можно брать в работу / нужно доработать / требует обсуждения

**Фазы проекта** (указываются при каждом запросе):
- КОНЦЕПЦИЯ — стратегические вопросы о смысле и целях
- ТРЕБОВАНИЯ — полнота и применимость
- ГОТОВАЯ ФУНКЦИОНАЛЬНОСТЬ — оценка как пользователь

## 3. Технический стек (текущий прототип)

**AI-модель:** DeepSeek (`deepseek-chat`)
- Выбран как бесплатная альтернатива для старта
- API совместим с OpenAI SDK
- Планируется переход на Claude API при масштабировании

**Текущие реализации:**

### 3.1 Telegram-бот (Python)
- Библиотека: `python-telegram-bot`
- AI-клиент: `openai` (с base_url DeepSeek)
- Конфиг: `.env` файл с `DEEPSEEK_API_KEY` и `TELEGRAM_TOKEN`
- Команды: `/start`, `/reset`
- Хранит историю диалога в памяти (по `chat_id`)
- Реализована одна персона: HRD (крупная компания)

### 3.2 Веб-приложение (HTML)
- Один файл `hrm_review.html` — чистый HTML/CSS/JS, без фреймворков
- Открывается локально в браузере, не требует сервера
- API-ключ вводится в интерфейсе (не хранится)
- Все 10 персон реализованы
- Персоны отвечают последовательно с индикатором печати
- Адресуется к DeepSeek API напрямую из браузера

**Текущие ограничения веб-приложения:**
- CORS: прямые запросы к DeepSeek API из браузера могут блокироваться — нужен backend или proxy
- Нет авторизации (планируется доступ по ссылке без логина)
- Нет сохранения истории сессий
- Нет загрузки файлов (только текст)
